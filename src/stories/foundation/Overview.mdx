# Foundation

This is the token layer the rest of the design system is built from — not a
component itself, so there's no single `Meta<typeof X>` under test the way
`Core/*`/`Layout/*`/etc. stories work. The source of truth is data:
`src/lib/theme/scales.ts` (raw scale values) and `src/lib/theme/reference/`
(the accessor registries built on top of them).

## Two layers, on purpose

**Primitive tokens** (`primitiveTokens`, `src/lib/theme/reference/primitive.ts`,
exported as `base` from `reference/index.ts`) are the raw palette/scale
steps — `ink`/`paper`/`oxblood`/`crimson`/`ghost`/`smoke`, font family/size/
weight/line-height/letter-spacing, space, screen, radius, opacity, duration,
easing. They are **internal** — `src/lib/theme/index.ts`, the theme's real
public barrel, does not re-export them.

**Semantic tokens** (`semanticTokens`, `src/lib/theme/reference/semantic.ts`,
re-exported as `tokens` from `@/lib/theme`) are the aliases built from
primitives, grouped by purpose — `tokens.color.text`, `tokens.background.page`,
`tokens.font.body`, etc. `semantic.ts` carries the repo's own instruction:
*"limit component usage to only semantic tokens"*. Every page in this section
documents primitives too, but strictly as **reference** — to show what a
semantic token resolves to, not as something to import into a component.

Both accessor families return `var(--...)` CSS references (see
`reference/utils.ts`'s `token.path`/`token.endPath`/`baseVar`/`aliasVar`),
never literal values — every swatch in this section is styled with the real
accessor, not a hex value copied out of `scales.ts`.

## A narrower public surface than it might look

`semanticTokens` itself only covers seven categories: `background`,
`breakpoint`, `container`, `color`, `font`, `opacity`, `motion`. Border color,
border radius, the full typography preset set (`text.h1`/`.body`/`.label`/
etc.), and the individual motion-transition properties all exist and are
genuinely emitted as CSS — but only through a separate internal registry
(`aliasTokens`, exported as `alias`) that `@/lib/theme`'s public barrel does
**not** re-export. Where a page below documents one of those, it's labeled
accordingly and referenced by its literal `--inkq-*` variable name (the only
way components reach it today), not a typed `tokens.*` accessor.

## Two real gaps found while writing this

Tracing `reference/semantic.ts` against the actual token-generation pipeline
(`buildSchemes.ts` → `tokens/*.ts` → `generate/strategies.ts`) turned up two
declared semantic accessors with no backing CSS custom property:

- `tokens.font.display() / .title() / .body() / .label()` — the real,
  composed typography presets are emitted as `--inkq-text-*` (`h1`, `h2`,
  `h3`, `h4`, `body`, `label`, `control`, `navigation`, `prose`, `caption`,
  `section.*`), not `--inkq-font-display` / `-title` / `-body` / `-label`.
- `tokens.motion.interactive()` — `MotionTokens` has no `interactive` key at
  all; the real transition vars are `--inkq-motion-background` / `-border` /
  `-color` / `-opacity` / `-transform` / `-box` / `-colors`.

See **Foundation / Typography** and **Foundation / Motion** for both,
demonstrated live via a computed-style readback of the actual (empty)
custom property.

## Color scheme

The theme has two schemes, `dark` (`ink`) and `light` (`paper`) —
`THEME_SCHEMES` in `scales.ts`. The generated CSS only reacts to a
`data-inkq-scheme` attribute on `:root`/`:host`
(`src/components/document/StyleInliner/resolver.ts`), with no per-element
scoping mechanism, so two schemes can't be painted side-by-side inside one
story. Pages with scheme-dependent content ship one story per scheme instead,
each setting the document-level attribute on mount via the same
`schemeControls()` helper the global Storybook decorator uses.

## Pages

- **Colors** — semantic `color`/`background` tokens (both schemes),
  measured WCAG contrast checks, primitive color scale reference.
- **Typography** — semantic `font.*` tokens (and the gap above), the real
  `text.*` presets, primitive type-scale reference.
- **Spacing** — semantic `breakpoint`/`container` tokens, primitive space
  scale, a sample of internal space-scale composites.
- **Motion** — semantic `motion.interactive` (and the gap above), real
  transition presets with live hover demos, primitive duration/easing scale.
- **Border** — internal border-color/radius presets (no public semantic
  accessor exists for these yet), primitive radius scale.
